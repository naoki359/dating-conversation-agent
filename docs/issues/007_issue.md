# [FEATURE] 返信内容の倫理・マッチングアプリ適合性チェックツールの追加

## 概要

生成した返信内容が倫理的かつマッチングアプリ文脈で適切かを自動判定するチェックツールを追加する。判定結果は `pass` / `review` / `block` の3段階とし、`review` または `block` 時は理由コードと改善提案を返す。

## 背景

現行フローでは返信生成後の安全性・適切性を体系的に検査する仕組みが不足している。マッチングアプリでは会話の自然さだけでなく、ハラスメント・差別・性的過剰表現・個人情報誘導・強引/操作的表現の抑止が重要であり、送信前の品質ゲートが必要である。

## 要件

- 対象は「生成された最終返信テキスト」とする
- Python/LangGraph の既存構成に統合可能なチェックツール（ノードまたはツール）として実装する
- 判定は `pass` / `review` / `block` の3段階とする
- `review` / `block` の場合は以下を返す
  - 理由コード（複数可）
  - 改善提案（具体的な書き換え方針）
- 最低限の判定観点を実装する
  - 倫理・安全性
  - ハラスメント/差別
  - 性的過剰表現
  - 個人情報誘導
  - 強引/操作的コミュニケーション
  - スパム性
  - マッチングアプリ文脈適合性（距離感・会話目的の妥当性）
- ルール追加・閾値調整を容易にするため、判定基準を設定化する
- 判定結果を JSON ログへ出力できるようにする
  - 例: `timestamp`, `user_id`, `session_id`, `message_id`, `decision`, `reason_codes`, `suggestions`, `version`
  - 個人情報は必要に応じてマスキングする

## 受け入れ条件

- 返信送信前にチェック処理が必ず実行される
- `pass` / `review` / `block` の判定が期待通りに動作する
- `review` / `block` 時に理由コードと改善提案が返る
- 判定観点ごとのテスト（正常系/境界値/NG例）が追加される
- 設定変更により閾値調整やルール追加が可能である
- 判定結果が JSON ログに出力され、後から分析可能である

## 補足

- 初期導入時は `review` を広めに設定し、運用ログを見ながら閾値を段階的に調整する
- 理由コードは将来の集計・改善に利用するため、体系的な命名（例: `HARASSMENT`, `PII_SOLICITATION`, `CONTEXT_MISMATCH`）を採用する
- 既存の `get_history -> generate_reply -> check_reply` フローに自然に組み込めるインターフェース設計とする
