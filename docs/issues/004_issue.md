# [FEATURE] エージェントのガードレール設計（ADLC Phase 1）

## 概要

エージェントが「何をやっていいか・ダメか」を自ら判断できるよう、目標・禁止事項・KPI・倫理制約・人間介入ルールを設計・実装する。

## 背景

エージェンティックマニュフェスト ADLC Phase 1「構想とガードレール」では以下を要求している。

> 従来：要件を細かく決める → ADLC：やっていい範囲・ダメな範囲を決める

現在のエージェントは「デーティングアプリの返信を生成する」という目的は実装されているが、どのような返信は許可されないか・どの程度の品質を目標とするか・いつ人間に判断を委ねるかが定義されていない。

エージェントの自律性を高めるほど、ガードレールの不在はリスクになる（不適切な返信の生成・無限ループ・倫理的逸脱など）。

## 要件

- **目標（Goal）** の定義: エージェントが達成すべきゴール（例：自分のプロフィールに合った自然な返信を生成する）をシステムプロンプトまたは設定ファイルに記述すること
- **禁止事項（Guardrails）** の定義: 生成してはいけない返信の種類（例：暴力的・差別的・過度に性的な表現）を列挙し、`DecisionNode` または `GenerateReplyTool` のプロンプトに組み込むこと
- **KPI** の定義: `fit_score` の目標値など、成功の定量基準を設定ファイルに記載すること
- **人間介入ルール** の定義: どのような状況で処理を中断し人間の確認を求めるかを定義すること（実装は 005_issue で行う）

## 受け入れ条件

- `DecisionNode` のプロンプトに目標と禁止事項が明示されていること
- 禁止事項に違反する可能性のある返信が生成された場合、`CheckReplyProfileFitTool` がそれを検出して低スコアを返すこと
- ガードレールの内容が設定ファイル（YAML or 定数）として管理されており、コード変更なしに更新できること

## 補足

- 対象ファイル（新規作成候補）:
  - `src/app/agent/core/config/guardrails.yaml`（禁止事項・目標の定義）
  - `src/app/agent/core/nodes/decision/prompts/`（プロンプトへのガードレール組み込み）
- ADLC の考え方では「作り方を決める」のではなく「ルールと目的を決める」ことが設計の本質
- このissueはシステムプロンプトの整備が中心となるため、コード変更よりもプロンプトエンジニアリングの作業が主体となる
