# [FEATURE] マルチエージェント構成への移行

## 概要

単一エージェント構成から、複数の専門エージェントが協調して動作するマルチエージェントシステム（MAS）へ移行する。エージェンティックマニュフェストの「エージェントの社会として構築する」という行動指針の実現を目指す。

## 背景

エージェンティックマニュフェストの行動指針「システムは単一のエージェントではなく、エージェントの社会として構築する」に基づく。

現在のエージェントは会話分析・返信生成・品質チェックをすべて一つのグラフで行っているが、それぞれの役割を専門エージェントに分割することで以下が期待できる。

- 各エージェントの責務が明確になり、プロンプトの最適化がしやすくなる
- 将来的に並列実行による高速化が可能になる
- 個別のエージェントを独立してチューニング・評価できる

なお、マニュフェスト自身が「複雑さは指数的に増加する」と警告しているため、必要な分割のみにとどめること。

## 要件

- 以下の専門エージェントへ分割することを検討する:
  - **AnalysisAgent**: 相手プロフィール・会話履歴を分析し、返信方針を決定する
  - **ReplyAgent**: AnalysisAgent の方針をもとに返信文を生成する
  - **ReviewAgent**: 生成された返信の品質・プロフィール適合性を評価する
- 各エージェントは LangGraph の独立したグラフとして実装し、スーパーバイザーエージェントが全体を統括する構成とすること
- エージェント間の通信内容（入出力）をログに記録すること（マニュフェストの「Agent conversation」要件）
- 各エージェントは独立してテスト・評価できること

## 受け入れ条件

- `POST /reply` を呼び出したとき、複数エージェントが協調して返信が生成されること
- 各エージェントの入出力がログに記録されており、どのエージェントが何を判断したかを追跡できること
- 単一エージェント時と比較して、返信の品質（`fit_score`）が同等以上であること

## 補足

- 対象ファイル（新規作成候補）:
  - `src/app/agent/agents/analysis_agent/`
  - `src/app/agent/agents/reply_agent/`
  - `src/app/agent/agents/review_agent/`
  - `src/app/agent/agents/supervisor/`
- LangGraph の `subgraph` または `Command` を活用したエージェント間通信を検討すること
- このissueは他の全issueが完了してから着手することを強く推奨する
- マニュフェストが指摘する「フィードバックループ・リソース競合・目標衝突」に対する設計を事前に検討すること
